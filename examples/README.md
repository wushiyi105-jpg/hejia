# examples · 四份真实报价单（已脱敏）

这里的四份报价单都不是编的:来自真实装修沟通里流传的那种表格(中介/工长发来的 Excel 或微信里贴的一段),只做了两件事——**去掉房号、联系人、公司名**,数字原样保留。

每份旁边的 `out/case-0N.md` 是**实际跑出来的输出**,第一行写着生成命令和运行日期。想看某个数字是怎么来的,把它粘回去跑一遍即可,结果逐字一致(离线模式不走模型,复算全在本地)。

| 文件 | 场景 | 城市 / 面积 | 这份报价的看点 |
|---|---|---|---|
| `case-01.txt` | 老房整体翻新半包,表格带表头 | 北京 / 89 ㎡ | 复算差 184、墙砖重复计费、管理费超区间 1.3 倍、9 处漏项 |
| `case-02.txt` | 厨卫局部改造,含一堆"按项" | 成都 / 68 ㎡ | 「拆改工程 项 2600」按项报价 1 处、防水小计多算 42、16 处漏项 |
| `case-03.txt` | 大平层半包,单价整体偏高 | 深圳 / 120 ㎡ | 6 处单价超上限(最高 1.9 倍)、乳胶漆换名重复计费、复算差 632 |
| `case-04.txt` | 出租房简装,只有 11 行 | 武汉 / 55 ㎡ | 4 行按项报价、1 处单价超上限、19 处漏项——越小越糙的典型 |

## 怎么跑

```bash
python -m hejia --mock audit --file examples/case-01.txt --city 北京 --area 89
```

`--mock` 是强制离线:不读 `.env` 里的 key,复算、对标、漏项、重复、问题清单全由本地规则出。配上 key 去掉 `--mock`,问题清单会换成模型写的版本,但**金额一栏仍然来自本地复算**。

## 两份读得出来的结论

- **表头行会进「未解析」提示,而不是被静默丢掉。** `case-01`、`case-03` 的第一行是「序号 项目 单位 数量 单价 小计」,它不该被当成报价行,也不该消失——输出里的「❓ 未解析」就是在提醒你:这一行我没敢算。
- **按「项」报价的项目分两种。** 闭水试验、垃圾清运、洁具安装这类本来就按项/套计价的,参考区间里也是按项,不该要求"按量计价";而「拆改工程 项 2600」「地砖铺贴 项 5200」这种拿"项"当挡箭牌的,必须揪出来。

## 已知的口径边界

- 漏项判定用的是词面匹配,「定制柜」对不上标准清单里的「定制柜体与五金」,会多报一条——宁可多报一条让你确认,也不要漏报。
- 城市系数是固定表(北京 1.25、成都 0.85……),不区分城区与工艺档次;它给的是"要不要问"的信号,不是定价依据。
